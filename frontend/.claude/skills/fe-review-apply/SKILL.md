# Fe-Review-Apply — PR 리뷰 반영 스킬

현재 PR의 리뷰 코멘트를 분류·검증해 타당한 것을 반영한다.
이 스킬은 `frontend/` 범위에서만 동작한다. `backend/` 파일은 수정하지 않는다.

> 규칙 기준: `AGENTS.md` 전체 컨벤션 표 (수정은 컨벤션을 따른다)

## Step 1: 리뷰 코멘트 수집

현재 브랜치의 PR에서 **모든 리뷰 코멘트**를 가져온다. `gh` CLI를 사용한다 (없으면 사용자에게 설치 요청 또는 코멘트 붙여넣기를 요청).

```bash
gh pr view --json number,title,reviews,comments
gh api repos/{owner}/{repo}/pulls/{number}/comments   # 인라인(라인) 리뷰 코멘트
```

각 코멘트의 **작성자·대상 파일:라인·내용**을 정리한다.

## Step 2: 작성자 구분

| 유형          | 식별                                                  | 태도                                                          |
| ------------- | ----------------------------------------------------- | ------------------------------------------------------------ |
| 사람(팀원)    | 봇이 아닌 계정                                         | 가능한 **존중하고 반영**한다. 의문이 있으면 반문·토론으로 해결 |
| AI 봇         | `coderabbitai`, `gemini-code-assist`, `claude`, `github-actions` 등 | **타당한 것만 선별**, 과한 nitpick은 적절히 필터링            |

- 사람 리뷰에 동의하기 어려우면 임의로 무시하지 말고, 질문으로 반문하여 의도를 확인하고 토론으로 합의한다.
- AI 리뷰는 근거가 약하거나 컨벤션·MVP 범위에 안 맞으면 필터링한다.

## Step 3: 분류와 판단 기준

각 코멘트를 셋으로 나눈다.

| 분류          | 판단 기준                                                                 | 처리                          |
| ------------- | ------------------------------------------------------------------------ | ----------------------------- |
| 반영          | 버그·접근성·타입 안정성·컨벤션 위반·명백한 개선                            | 이번 PR에서 바로 수정         |
| 검토 필요     | 설계 변경·구조 리팩토링·범위 확대가 필요한 것                             | 사용자와 상의, 필요 시 PR 분리 |
| 무시          | 과한 nitpick·취향 차이·근거 약함·MVP 범위 밖·이미 의도된 코드             | 사유를 남기고 미반영          |

분류 결과를 표로 먼저 사용자에게 제시한다 (작성자·위치·분류·사유).

## Step 4: 수정 작업

"반영"으로 분류한 항목을 수정한다.

- 수정은 `AGENTS.md` 컨벤션을 따른다. 코멘트가 컨벤션과 충돌하면 컨벤션을 우선하고 그 사실을 알린다.
- "검토 필요"는 사용자 합의 전까지 손대지 않는다.
- 한 코멘트 수정이 범위를 크게 벌리면 멈추고 PR 분리를 제안한다.

## Step 5: 검증과 보고

수정 후 검증한다 (`fe-qa` 스킬 또는 `AGENTS.md` "검증" 표).

```bash
pnpm --dir frontend exec tsc -b
pnpm --dir frontend run lint
pnpm --dir frontend test
```

결과를 아래 형식으로 보고한다.

```markdown
## 리뷰 반영 결과

| 작성자 | 위치 | 분류 | 처리 |
| ------ | ---- | ---- | ---- |
| @user  | Foo.tsx:42 | 반영 | aria-label 추가 |
| coderabbitai | Bar.ts:10 | 무시 | 취향 차이, 근거 약함 |

### 검토 필요 (사용자 확인)
- Baz.tsx: 구조 리팩토링 제안 → 별도 PR 제안

### 검증
tsc / lint / test: ✅ 통과 / ❌ 실패 (내용)
```

미반영·검토 필요 항목은 사유와 함께 남겨 사용자가 판단할 수 있게 한다.
